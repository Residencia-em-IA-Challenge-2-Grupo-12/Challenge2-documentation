# Requisitos Não Funcionais

<p align="center">Tabela 2: Requisitos Não Funcionais</p>

| ID | Descrição | Implementado |
|:---|:---|:---|
| <a id="RNF01"></a>RNF01 | Ser um sistema/app com uma identidade visual boa de utilizar. | Não |
| <a id="RNF02"></a>RNF02 | Modo noturno/diurno. | Não |
| <a id="RNF03"></a>RNF03 | Widget para smartphone. | Não |
| <a id="RNF04"></a>RNF04 | Acesso a notas e horários restrito à conta do próprio usuário, sem compartilhamento com outros usuários ou terceiros. | Não |
| <a id="RNF05"></a>RNF05 | Notificações, rótulos ou indicadores de atraso quando a meta semanal de uma matéria não for atingida. | Não |
| <a id="RNF06"></a>RNF06 | Upload e a geração de resumos de até 50 páginas, por exemplo, não devem passar de 60 segundos. | Não |
| <a id="RNF07"></a>RNF07 | Memória de histórico de aprendizado, por pelo menos 90 dias (ou menos). | Não |
| <a id="RNF08"></a>RNF08 | Dados pessoais de rotina, sono e compromissos devem ser tratados conforme a LGPD, com consentimento explícito e opção de exclusão de conta e dos dados. | Não |
| <a id="RNF09"></a>RNF09 | A integração com o Google Calendar deve conter somente a permissão de leitura, coerente com a sincronização unidirecional. | Não |
| <a id="RNF10"></a>RNF10 | O sistema deve ser uma aplicação web responsiva, usável em navegadores, tanto de desktop quanto de dispositivos móveis. | Não |
| <a id="RNF11"></a>RNF11 | Lembretes e notificações devem usar Web Push no navegador, depois que o usuário der permissão. | Não |
| <a id="RNF12"></a>RNF12 | Toda sugestão de estudo deve vir com uma justificativa em linguagem simples, citando os fatores considerados: prazo, faixa de rendimento e sono. | Não |
| <a id="RNF13"></a>RNF13 | A importação de .csv deve validar as colunas obrigatórias e informar quais linhas são inválidas, sem descartar as válidas. | Não |
